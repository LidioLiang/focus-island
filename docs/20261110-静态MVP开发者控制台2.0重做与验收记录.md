# 静态 MVP 开发者控制台 2.0 重做与验收记录

日期：2026-11-10（Asia/Shanghai）  
阶段：静态 Web MVP 上线质量收口 / 6E 封测准备  
产品版本：1.1.2；开发者工具版本：2.0。基于 Production `0909da5d19310caa7c5e4205ec678ee2d318e67b`。

## 现场问题

使用已授权开发者账号打开正式站，确认旧面板实际为 1.1.1，但存在中英混杂、侧栏版本写死、原始 JSON 占据主体，以及在海岛上不能处理云端遗留会话的问题。不是单纯浏览器缓存。

## 本轮实现

- 产品版本统一从 package.json 读取，同时显示工具版本、环境、构建 SHA；JS/CSS 更新缓存版本。页面与服务器版本不一致时提示刷新并禁用会话操作。
- 控制台重做为版本信息、三间真实共享房间、当前设备状态、本账号云端会话、静态座位工具；原始 JSON 收入折叠面板。明确快照时间，失败保留上次快照；不可用房间显示未知，不伪造零占座。
- 每间房展示六个真实座位状态，标记本账号座位；API 不返回其他用户的身份信息。
- 海岛上可以读取并明确确认结束自己的遗留测试会话；确认时锁定会话 ID，刷新不能把目标换成新会话。继续计时仍须先选座，所有开始操作仍经过原有资格校验，不重置试用。
- 普通账号没有入口；服务端在查询前校验 developer 角色，角色撤销后关闭开发者页。只调用原有用户所有权限定的专注更新 RPC，不新增管理他人会话的权限。
- 正式房间入口无条件使用静态六座视图；旧 Godot 查询参数、存储偏好、旧调试按钮均不能将正式咖啡馆带回历史编辑器。内部 3D 研发文件保留。
- 控制台提供完整中英文文案、响应式布局；可从海岛进入咖啡馆，再校准固定座位编号或恢复静态视图。

## 验证与发布

- 干净隔离副本：ESLint、TypeScript、87/87 Node 测试、Next.js 生产构建通过。源工作区的旧 .next 存在重复生成类型文件，隔离构建已排除该缓存干扰。
- 新增 6 项执行真实函数的 Node 检查：双语和真实状态、确认锁定目标、普通权限/版本不匹配拦截、失败保留快照及角色撤销、旧渲染偏好隔离、诊断脱敏与部分失败。
- 新增 3 项 Chromium 回归：完整开发者面板及取消/确认结束、普通用户隐藏工具、历史 3D 偏好下仍进入静态房间。待 CI 执行结果填写。
- 发布分支仅包含本轮相关文件，保留既有 3D 八座研发测试修改和未提交落地页预研。
- 发布状态：本地通过，CI 与正式发布核验进行中；不得据此宣称新版本已上线。

普通用户长时全链路、其他浏览器、支付生命周期和完整商业发布门禁继续按现有清单追踪。
