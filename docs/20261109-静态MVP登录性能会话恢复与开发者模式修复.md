# 静态 MVP 登录性能、会话恢复与开发者模式修复

日期：2026-11-09（Asia/Shanghai）  
阶段：静态 Web MVP 上线质量收口 / 6E 封测准备  
修复版本：1.1.1；基于当前 Production 提交 `904b9f3`。  
发布状态：本地修复与构建通过；正在准备独立修复分支和 CI 验证，尚不能宣称生产已更新。

## 问题与证据

1. 用户反馈登录慢、进入后卡顿、中途退出后被上次专注阻塞。
2. `proxy.ts` 原来对公开图片、JS/CSS、音频与 API 请求都执行 Auth 刷新；API 自身还会验证用户。生产 API 在 `iad1`、数据库在新加坡，重复跨区请求放大延迟。
3. 登录 API 已查询使用资格，但客户端又顺序查询资格、导入历史后才进入海岛；进咖啡馆还再次查资格和身份。
4. 房间的 `back-island` 原来只释放座位，不结束 `focus_sessions`。远程 PostgreSQL 日志也出现多次 `active_session_exists`。
5. 服务端资格查询的历史平均数据库执行时间约 4ms，开始专注约 22ms；这些不是浏览器端到端耗时，不能用来宣称登录已达到某个秒数。
6. 旧会话冲突仅显示等待提示，没有恢复操作；结束请求失败被直接忽略，可能丢失云端收尾。
7. 开发者页还提供旧家具/人物图层编辑器，与当前静态 MVP 不符。

## 修复

- 公开资源与 API 不再在 Proxy 重复刷新 Auth；已登录首页仍刷新，API 继续逐次服务端认证与权限验证。
- 注册/登录返回服务端资格结果，客户端复用并合并同时发生的资格查询；历史导入不再阻塞首次进入。进房可短暂复用刚取到的资格，最终分房/开始仍由服务端检查。
- API 请求设置 15 秒超时，避免请求无限等待。
- 主要海岛、咖啡馆和四个近景生成等尺寸 WebP 发布副本，原 PNG 保留；六张资源总计从 16,593,136 字节降为 2,080,412 字节，减少约 87%。源资产权属不变，转换工具为项目现有 Sharp，未新增第三方图片。
- 房间快照无变化时保留原人物/热点 DOM，减少不必要的重建。
- 活跃专注返回海岛前明确确认，保存专注并释放座位；结束写入失败时本地保留待同步队列，登录/联网/下一轮开始前重试。
- 409 冲突可以读取本账号活动会话，选择继续上次或明确结束上次再开始。继续使用原 client session ID；重新开始必须重新通过服务端试用/付费授权，不返还已消耗试用，不自动结束他人或其他会话。
- 并发点击开始共用一个授权请求；已结束的旧 ID 不再被 API 当作可继续的活动会话。
- 刷新后休息已结束时，下一轮保持未开始，避免未经授权自动运行。
- 开发者页升级为静态 MVP 版本/渲染/座位/会话诊断，提供只读在线诊断、旧会话恢复、恢复静态视图与固定座位编号校准。旧场景编辑器入口移除。
- 新 `/api/developer/diagnostics` 在读取任何数据前检查服务端 developer 角色；只输出房间聚合占用和本账号活动会话，不输出密钥或其他用户身份。
- 旧内部渲染器偏好迁到 V2；普通用户不能因旧查询参数进入 Godot 页面。

## 验证

- 修复提交的干净副本：ESLint、TypeScript、81/81 Node 测试、Next 生产构建通过。
- 新行为测试执行实际前端函数，覆盖重复点击、409 恢复、原会话续用、试用耗尽后仍受付费墙拦截、失败收尾重试、登录不等待历史导入、资源不触发 Auth、普通账号不能读开发者诊断。
- 新增 Chromium 浏览器回归：确认离开后云端收尾；冲突后先结束旧会话再创建新会话。
- CI 增加 Chromium 安装和现有/新增 E2E。当前本机环境禁止监听服务端口与启动 Chromium，浏览器用例须在 CI 执行；不能把启动失败记为浏览器验收通过。
- 未迁移生产区域、改套餐、改支付价格、修改现有专注业务数据或扩大场景范围。
- 修复分支只收录本次相关文件；原工作区既有 3D 契约测试与未提交落地页预研文件保持原状。

## 发布后需复测

使用普通账号和开发者账号分别检查登录、进入咖啡馆、开始/暂停、返回房间、确认退出、再次进入及旧会话恢复；普通试用账号必须继续受一次试用限制。检查开发者页版本为 1.1.1，图片请求为 WebP。

卡顿还可能受设备、浏览器、跨区网络和实际资源缓存影响；本轮完成了可确认的代码与下载量优化，尚无用户设备端到端性能基准，不承诺具体倍数提升。
