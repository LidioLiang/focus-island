# PostHog 匿名漏斗接入与验收记录

日期：2026-11-15  
阶段：海外冷启动并行项——线上用户观测与前 100 名试用者验证  
版本：v1.6.3

## 目标

在不增加注册门槛、不启用录屏和全站自动点击采集的前提下，确认真实访客是否完成专注岛的核心闭环：

1. `landing_viewed`：同意分析后访问产品。
2. `scene_selected`：选择咖啡厅、图书馆或森林。
3. `seat_confirmed`：服务端或本地房间确认座位。
4. `focus_started`：真正开始计时，不把选座或打开计时界面算作开始。
5. `focus_finished`：完成、提前结束或中断一轮专注。

D1/D7 留存以同一匿名或账号标识再次出现 `focus_started` 为准，不额外伪造“回访”事件。

## 实现边界

- 使用 PostHog US Cloud 公开采集端点；Project Token 和 Host 通过 Vercel 的 `NEXT_PUBLIC_POSTHOG_PROJECT_TOKEN`、`NEXT_PUBLIC_POSTHOG_HOST` 注入。
- 首次访问展示非阻塞分析选择；未明确允许前不发送任何分析事件。设置和隐私政策均可重新打开选择面板。
- 仅允许上述五个产品事件；未知事件和未列入白名单的属性在浏览器端直接丢弃。
- 不启用 session replay、autocapture、广告追踪或自动 pageview。
- URL 只发送 origin + pathname；OAuth code、密码恢复参数和其他 query 不会发送。
- 不发送邮箱、显示名、头像地址、任务文字、声音偏好、支付信息或专注历史明细。
- UTM 仅允许 `utm_source`、`utm_medium`、`utm_campaign`、`utm_content`、`utm_term`。
- 开发者账号识别后停止发送；正式分析时继续按 `is_developer = false` 过滤。
- 匿名 ID 保存在浏览器本地；获得 Supabase 用户 ID 后用 `$identify` 连接匿名阶段与后续事件。退出账号会生成新的匿名分析 ID。

## 事件属性

| 事件 | 允许属性 |
| --- | --- |
| `landing_viewed` | 五个 UTM 字段 |
| `scene_selected` | `scene_id` |
| `seat_confirmed` | `scene_id`, `seat_id`, `room_type` |
| `focus_started` | `scene_id`, `seat_id`, `room_type`, `timer_mode` |
| `focus_finished` | 上述专注属性 + `actual_seconds`, `result` |

所有事件另带版本、部署环境、匿名/开发者标记和不含查询参数的页面路径。

## PostHog 首批看板

上线并收到首批事件后创建以下 Insights：

1. 漏斗：`landing_viewed → scene_selected → seat_confirmed → focus_started → focus_finished`，窗口 24 小时。
2. 完成质量：`focus_finished` 按 `result` 拆分，重点看 `completed / focus_started`。
3. 场景转化：按 `scene_id` 比较 `focus_started → focus_finished`。
4. 获客质量：按 `utm_source`、`utm_campaign` 比较开始率与完成率，而不是只看访问量。
5. 留存：首日事件 `focus_started`，回访事件 `focus_started`，观察 D1 与 D7。

所有看板默认排除 `is_developer = true`。首批样本不足 30 人时只查看逐条会话路径，不据小样本优化定价或大改产品。

## 尚未完成的外部门禁

- 需要正式域名的真实非开发者浏览器允许分析并完成一次专注，确认事件在 PostHog Live Events 中到达。
- 需要收到真实流量后在 PostHog UI 创建漏斗和留存 Insights；当前没有 PostHog Personal API Key，不通过私有 API 代建看板。
- 跨浏览器、广告拦截器和网络受限环境可能阻止第三方分析请求，不得把 PostHog 数量当作绝对访问量。
