# 2026-11-13 选座后落座停顿与沉浸过渡（v1.5.4）

范围：静态 MVP 的咖啡厅、学院图书馆和森林区共用选座流程。用户希望选座成功后不要立即切换，而是在房间停顿 2–3 秒，再自然进入沉浸桌景。

## 实现

- 网络占座确认阶段仍即时显示 `Preparing seat …`，不人为拖慢服务响应。
- 座位确认成功后先重新渲染房间，显示用户头像已坐到所选位置，并以无障碍状态文案显示 `Seat N is ready. Settling in…`。
- 房间停留 1900ms 后，将对应沉浸桌景覆盖层以 600ms 淡入，总落座过渡约 2500ms；桌景在停留期间预解码，减少切换时闪白。
- 过渡完成前不渲染 `Return to focus`，其他座位保持禁用，避免重复点击或绕过停顿。完成后才显示沉浸计时界面，计时仍保持未启动状态，用户继续通过 Start 明确开始。
- 减少动态效果开启时保留同样的停顿时长，但 CSS 取消渐变动画。
- 视觉过渡失败时不撤销已确认座位，安全降级进入沉浸桌面。
- JS/CSS 缓存版本更新为 app.js v55、minimal-mvp.js v9、minimal-mvp.css v6；产品版本更新为 v1.5.4。无数据库迁移。

## 验证

- Node 124 项、lint、typecheck、production build 已通过。
- Chrome 本地真实操作确认：选座后 272ms 时仍停留在房间，头像已落座，状态文案可见，其他座位禁用；随后自动进入沉浸桌面。
- 新增 Chromium 回归：选座确认后头像和状态文案出现；前 1500ms 不出现计时器；淡入层出现；至少 2300ms 后才进入 25:00 桌景。完整 CI 与 Preview/Production 验收待发布流程补充。
