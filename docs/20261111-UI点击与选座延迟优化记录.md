# 2026-11-11 UI 点击与选座延迟优化（v1.5.1）

阶段：静态 MVP 线上交互性能修复；咖啡厅、图书馆、森林共享流程。

## 已定位与修复

- 极简浮层的 checkbox/range/input 点击冒泡，被历史 `.session-control-panel` 外部点击处理当作关闭面板，重建整个 focus DOM，吞掉第一次操作。极简模式退出该旧路径，由现有 pointerdown 浮层规则处理关闭。
- 房间首次快照无变化也重建所有选座按钮，可能在按下与松开之间丢失按钮。首次渲染同时初始化 render key，无变化保留 DOM 节点。
- 新入座串行等待 reserve、occupy、state 三次 HTTP。新增 `reserve_and_occupy_seat`，在一笔事务内复用现有锁、身份/归属/房间/座位检查。仅服务端确认成功后进入专注，名单异步刷新；递增快照版本使旧响应无效。旧客户端仍可使用分步接口，换座保持既有流程。
- 选座、进入房间、开始计时增加即时可访问的处理中反馈；等待时阻止重复开始和切换流程。失败选座恢复操作，不等待再次同步。
- 极简进入房间不再额外请求 access/status，allocate 仍在服务端完整校验并返回 access；身份认证未放松。
- 设置面板可先操作，身份查找返回后仅权限真正变化且仍在设置面板时更新，避免无意义的输入重置。
- API 从 iad1 调整为 sin1，与现有生产 Supabase ap-southeast-1 同区。数据库、用户数据及产品目标市场不迁移；Preview 测试库仍在美国，不能用于生产性能对比。

## 验证

- 本地 lint、TypeScript、124 项 Node、生产构建通过。
- 新增 4 项浏览器回归：原生开关首次点击；按住座位期间快照刷新；慢速原子入座不等待名单；占座冲突可重试；慢速开始的防重复和导航保护（其中选座测试合并多个断言）。
