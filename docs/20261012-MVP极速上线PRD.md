# MVP 极速上线 PRD

创建日期：2026-10-12  
当前策略：先上线一个可用、可测试、可收集反馈的最小版本，不追求成熟工程化。

## 1. 一句话目标

让用户打开链接后，能在 15 秒内进入咖啡厅，选一个座位，开始一次 25 分钟专注，并在结束后留下反馈。

## 2. 当前唯一主线

- 代码入口：`prototype/`
- 当前上线版本只做：咖啡厅专注房间
- 暂停继续做：多场景扩展、大规模前端拆分、复杂测试体系、登录系统、付费、完整数据看板

## 3. MVP 只验证一件事

安静的虚拟陪伴和氛围感，能不能让用户更愿意开始并完成一次 25 分钟专注。

## 4. 必须有

1. 首页能打开。
2. 用户能进入咖啡厅。
3. 用户能选择座位。
4. 用户能开始 25 分钟专注。
5. 用户刷新页面后，计时状态尽量不丢。
6. 用户能暂停、继续、结束。
7. 结束后能看到本次专注时长。
8. 结束后有一个反馈入口。
9. 咖啡厅画面、座位、角色显示稳定。
10. 桌面 Chrome 和 Safari 能完成一次完整流程。

## 5. 暂时不要做

- 不做新场景。
- 不做注册登录。
- 不做付费。
- 不做复杂排行榜、成就、历史统计。
- 不做完整多人系统扩展。
- 不继续大拆 `public/app.js`。
- 不继续追求测试覆盖率。
- 不做移动端深度适配，只保证不崩。
- 不做复杂后台。

## 6. 当前开发路径

### 第 1 步：冻结范围

只保留咖啡厅作为公开测试入口。图书馆、森林、海岛扩展都可以留在界面里，但不再作为上线前必须修好的内容。

验收：用户不需要理解整个世界观，也能直接开始专注。

### 第 2 步：修通主流程

主流程为：

```text
打开链接 -> 进入咖啡厅 -> 选座 -> 开始 25 分钟 -> 暂停/继续/结束 -> 反馈
```

验收：连续 5 次手动测试都能走完，不出现卡死、白屏、按钮无效。

### 第 3 步：加一个反馈入口

最简单可以先用外部表单链接，或者一个 `mailto:` / 表单按钮。不要为了反馈系统新建后台。

反馈只问三件事：

1. 你有没有更容易开始专注？
2. 你愿不愿意明天再用一次？
3. 哪里最影响你继续使用？

验收：测试用户结束后能留下反馈。

### 第 4 步：上线前只做最小检查

上线前只检查：

- `npm run check` 通过。
- 首页可打开。
- 咖啡厅主流程可完成。
- 控制台没有阻断错误。
- GitHub 已有可回滚提交。

验收：可以发给 5 到 20 个真实用户试用。

### 第 5 步：小范围内测

先不要追求 100 人。第一轮只找 5 到 20 个目标用户。

目标不是增长，而是确认：

- 他们能不能自己完成流程。
- 他们是否真的坐下来专注。
- 他们是否愿意第二天再打开。

## 7. 成功标准

第一轮只看 3 个数字：

- 10 人打开链接。
- 7 人成功开始一次 25 分钟专注。
- 3 人第二天愿意再用。

达到后，再考虑恢复 P1 工程化和多场景路线。

## 8. 对当前项目的处理原则

已经做过的 P1 工程底座、质量门禁和前端拆分可以保留，但不要继续扩大。

当前每次开发只问一个问题：

这件事能不能帮助我们更快让真实用户完成一次 25 分钟专注？

如果不能，先不做。

## 9. 下一个最小任务

检查当前 `prototype/` 是否已经能稳定完成咖啡厅主流程。如果能，下一步只补反馈入口；如果不能，优先修主流程，不做任何新功能。
