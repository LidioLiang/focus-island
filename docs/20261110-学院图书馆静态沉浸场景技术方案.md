# 学院图书馆静态沉浸场景技术方案

日期：2026-11-10（Asia/Shanghai）。阶段：极简 Web MVP 第二场景扩展，技术设计。
状态：用户已授权实施，学院图书馆 v1.4.0 已完成代码与美术集成；发布状态与独立审查结论见同日实施验收记录。
依据：用户最新要求、20261110 极简陪伴与专注重新定位方案、当前本地 v1.3.2 源码。早期文档中的坐姿人物、NPC 陪伴、Godot 和仅开放咖啡馆的范围以用户后续决定为准。

## 1. 建议方案

沿用咖啡厅已使用的技术栈：Next.js + HTML/CSS/JavaScript + 静态高质量图片 + Supabase Auth/Postgres/RPC/Realtime。图书馆与咖啡馆共用身份、头像、选座、计时、声音控件和会话恢复。

用户路径：海岛书本地图钉 → 后台自动分配图书馆房间 → 点击空座 → 打开对应的第一人称桌面/窗景 → 用户点击 Start 后开始计时和声音。

首版建议：一套六座房间布局、三个沉浸近景、一个图书馆专属环境声预设。房间只显示真实用户头像和轻微专注波纹；保留 Solo room 降级，不伪造其他用户。不增加手动选房、角色移动、换装、奖励或独立的一套登录流程。

- 20261015-library-template-stage-wide.png：1764×992，约 3.0 MiB，主要是留有空地的建筑背景。

## 3. 场景与美术生产

对外英文名建议 Academy Library，内部 ID 使用 library。

房间画面：学院式高窗、木书架、暖台灯、自然光、少量植物；延续咖啡馆的温暖半写实风格，减少大厅空旷感。完整母图一次性包含桌椅；六个可选席位明确、分布舒展，无假用户人物。不能依靠全景截图放大来冒充近景。

| 座位 | 区域 | 默认沉浸近景 | 近景内容 |
| --- | --- | --- | --- |
| 1–2 | 临窗书桌 | Window Desk | 眼平视角，近处木桌与书本，远处庭院/学院窗景 |
| 3–4 | 中央阅读桌 | Reading Table | 台灯、桌面、书架，远处可见同一建筑的高窗 |
| 5–6 | 安静阅读角 | Quiet Alcove | 半包围书架、小窗、暖灯，强调安定与私密感 |

两席共享一张近景即可，不为六席各做一张新图。默认按座位分区选近景，也允许用户在场景按钮里切换；切近景不换房、不释放座位、不重置计时。

首版新增核心素材：一张完整六席母图、三张近景、一个无突兀接缝的环境声循环。地图和书本图标、头像、字体、音乐及白噪音控件复用。所有新增素材记录来源、制作日期及公开使用权。

先做“母图 + 临窗近景”两个主样，验证同一建筑、同一光线风格和六席布局后，再补另两张近景。

## 4. 按配置复用场景能力

先为两个场景建立一个受控清单，数据字段包括：

- id、label、enabled、mapMarker。
- roomImage、designSize。
- seats：六个 seatId，各自的 buttonAnchor、avatarAnchor、zoneId、defaultFocusView。
- focusViews：viewId、图片、缩略图、英文标签及手机裁切焦点。
- audioPreset：环境声资源、默认音量及英文标签。
- layoutVersion。

字段是建议的数据契约，不代表已经新增运行代码。前端使用资源/座位配置；服务端对允许的场景与房间进行验证；数据库 room_instances 维护实际房间实例。上线开关需要前后端与数据库一致，不能仅修改前端标识。

改造范围集中在当前极简路径，抽出 enterSceneRoom、场景状态刷新和近景选择等公共能力。保留必要兼容入口，不全局替换所有 cafe 字符串，也不顺手重写历史 3D 研发目录。

场景独立保存：最后选择的近景、环境声预设和开发者坐标。旧 lastFocusView/布局 key 仅迁移到 café；不得让咖啡馆雪景选项或头像坐标串到图书馆。“回到上次的位置”“再来一段”、离线房间、恢复会话及历史标签都必须使用实际 sceneId。

开发者导出布局应带 sceneId、layoutVersion、designSize 和六席坐标；校验后随版本发布。本机 Save 继续明确只作用于当前浏览器，不能声称已同步到所有用户。

## 5. 在线与数据改造

首期建议新增 library-01、library-02、library-03，每间六席，共 18 个图书馆在线座位。它们与咖啡馆共用现有服务和 Supabase 项目，不需要每个房间单独启动服务器。18 是配置的可选座位数，不是服务器经过压测的并发承载上限。

- 自动分房仅在目标场景中选择，优先已有真人但未满的房间。
- 恢复旧房间前必须确认旧 roomId 属于目标 sceneId，防止点击图书馆后恢复到咖啡馆。
- 复用原子抢座、15 秒预留、确认占座、15 秒心跳和 45 秒占座租约。断线后的清理按现有租约语义工作。
- 同一账号跨场景仍只有一个活跃专注；切换真实场景需先确认结束并释放旧座位，不能直接改 sceneId 绕过限制。
- 房间 ↔ 沉浸视图不换 session；library 内切换近景也不换 session。
- 服务端验证 scene/room/seat 关系与当前用户权限；在线座位核验当前用户拥有的租约。离线/Solo 会话使用明确的 library-local 语义，不能伪称在线。
- Realtime 继续广播 room:{roomId}:leases 的状态变化；使用私有频道并检查授权策略是否包含新房间。资源图片和个人声音设置不经过 Realtime 广播。
- 离开房间时解除旧订阅和轮询；慢请求/重连回包必须匹配当前场景和会话，避免快速切换场景时串房。
- 满员或在线服务失败时提供明确 Solo room；不在专注中途强制迁移到后来出现空位的在线房间。

数据库通过新增迁移扩展，不修改已执行的历史迁移。先在预发布验证，再发布代码与正式配置。新房间初始可保持 disabled，最终验收后再同时开放海岛入口。

## 6. 沉浸 UI、适配及性能

沿用当前已确认的 UI：默认窗景 + 计时；左上只有返回箭头；右上依次场景、声音、设置、头像。计时操作位于数字下方；25 min / 50 min / Open 同排。显示文案原生英文，名称不再硬编码成 café。

- 房间锐利母图保持完整比例，百分比坐标相对同一设计画布；空余视口使用同图模糊背景填满。
- 沉浸图全屏铺满，手机按构图焦点裁切；桌面和窗景的重要内容不能被计时与菜单遮住。
- 390px 手机、横屏和平板均检查六个热点不重叠、按钮居中、触控目标不小于 44px；在母图构图时就预留间距。
- 核心图导出 WebP 与适配尺寸；原始大 PNG 不直接作为首屏资源。
- 目标预算（待实测）：房间桌面图 0.4–0.8 MiB；单张近景不超过约 1 MiB；手机提供更小版本，缩略图单张约 60 KiB 内。质量检查优先于机械压缩到固定数字。
- 进入图书馆只优先加载本场景母图；房间首屏就绪后按带宽预取默认近景，其他近景按需加载。首页不预载全部图书馆资源。
- 尺寸预留避免布局跳动；低清占位到清晰图用短淡入。加载失败仍可继续本地专注，不无限转圈。
- 第一阶段主要靠构图、材质和声音实现沉浸；只保留现有头像波纹和短淡入。低频动效优先 transform/opacity，减少动画时关闭。
- 后续可在同一配置上增加窗口遮罩下的雨、树影或局部暖光层，按效果与性能验证逐项增加。无需先引入视频常驻播放、Canvas 引擎、PixiJS 或 3D。

声音界面把 Café ambience 改成场景对应的 Library ambience。复用混音/白噪音/音乐开关，增加安静室内、轻风或雨声等专属循环，避免清晰人声和突兀翻页。音乐默认关闭；用户已有静音选择不能被换场景偷偷覆盖。音频只在用户主动开始/开启后播放。

## 7. 实施顺序与交付

1. 美术主样：完整六席母图 + 一张临窗近景；确定风格、比例、六席清晰度和手机布局。
2. 公共能力：场景清单、当前极简渲染/声音/回访流程按场景配置；咖啡馆原体验回归通过。
3. 图书馆纵向闭环：先用一个近景打通分房、抢座、头像、计时、记录和恢复；接口与数据库在预发布通过验证。
4. 内容补全：增加阅读桌/安静角两张近景、专属环境声及开发者独立坐标校准。
5. 发布验收：浏览器、并发与长时检查完成后开放书本地图钉；保留独立开关，出问题时只关闭图书馆入口。

以这些交付为排期单位；不把尚未确认的美术迭代次数或真实网络门禁包装成确定上线时间。

## 8. 上线验收清单

- 新访客从海岛到图书馆选座和开始计时，无须注册、填表或选房号。
- 两个独立客户端同抢一个座位，只允许一个成功；另一场景的同号座位不受影响。
- 两端能够看见真实头像/昵称和更新；不显示伪造陪伴或过期“专注中”。
- 25/50/Open 开始、暂停、继续、结束、再来一段都正确记录 library，历史显示 Academy Library。
- 回房间、改近景、后台运行不重置时间；刷新恢复正确场景、座位与会话；断线、旧租约、旧会话不会卡住新一轮。
- 正在专注时跨场景切换走确认与收尾；快速切换/晚到回包不串房。
- 默认及首次渲染均英文；头像/昵称跨场景共享；无声/减少动画/键盘和触屏均可用。
- 不同设备全屏无空白、热点准确、六席不重叠；开发者面板可移开，六号座位可调整，咖啡馆布局不被覆盖。
- 服务失败可明确进入 Solo room，恢复网络不打断当前专注。
- 咖啡馆全部已有回归继续通过；新增图书馆浏览器/数据库用例，以及 Safari、手机和 25/50 分钟真实长时检查。测试通过只代表所覆盖环境，不宣称无限并发。

## 9. 后续扩展方式

下一个海滨/森林场景主要新增母图、近景、坐标、环境声及房间配置。头像、计时、在线占座、开发者工具和账户继续共用。局部环境动效作为可选表现层，不承担房间真值、计时或权限判断。
